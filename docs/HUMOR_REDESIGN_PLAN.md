# План: упрощение юмора Тимура + полное автотестирование

Выполняется по `docs/LLM_HUMOR_REDESIGN_PROMPT.md`. Цель — не подлатать adaptive humor, а сделать Тимура объективно смешнее: меньше навязчивых и неуместных реплик, выше качество отправленных.

## 0. Цель в объективных терминах

«Смешнее» фиксируется воспроизводимыми измерениями на фиксированном корпусе сцен, а не мнением:

| Метрика | Что означает «объективно лучше» | Где видно |
| --- | --- | --- |
| `gate_accuracy` | корректный выбор joke/silence/react против золотых меток корпуса | Layer A автотесты |
| `anchoring_rate` | доля отправленных реплик, цепляющихся за конкретную деталь сцены (token-overlap с триггером) | harness + replay |
| `template_violations` | запрещённые шаблоны/отсутствующие люди после фильтров — строго 0 | автотесты |
| `repeat_rate` | повторы против `recent_outputs` — 0 на фиксированном корпусе | harness |
| `silence_precision` | не встревать там, где повода нет (техвопрос, серьёзная тема, законченная шутка человека) | golden scenes |
| `mechanism_diversity` | нет зацикливания на одном механизме | `humor_stats_v2` |
| `sent_quality` (live) | ❤️ и явный смех на отправленное, отсутствие `/unfunny` | `humor_stats_v2`, метрики в `humor.py` |

Успех: новая версия не хуже старой по `silence_precision` и лучше по `anchoring_rate`/`gate_accuracy` на том же корпусе — без роста токсичности и частоты ответов.

## 1. Диагностика (по коду, факты)

- Два контура без общего владельца качества: прямой ответ (`build_chat_messages`, `bot_logic.py:3760`) и ambient pipeline (`_maybe_send_adaptive_snipe`, `bot_logic.py:4165`).
- Каскад гейтов в ambient-пути: три счётчика `min_human_messages_*` + cooldown + `participation_rate=0.225` + бюджет + writer-abstain + фильтры + Critic ≥ 85. Каждая ступень независимо убивает попытку; выживание в каскаде важнее смешности.
- `director_max_tokens=180` на JSON с setup/target/relation/forbidden_moves + 4 кандидатами — риск обрезания вывода ⇒ `parse_director` вернёт пусто, бюджет потрачен впустую.
- `interjection_timeout_seconds=3` на Writer+Critic (два LLM-вызова) — таймаут раньше завершения ⇒ тихая потеря ресурсов.
- Обратная связь пишется (`humor_stats_v2`, `_rebuild_mechanism_stats` в `humor.py:574`), но не поступает в Writer/Critic — видимость обучения подтверждена.
- Тесты доказывают контракты, лимиты и тишину, но не качество юмора. Fixture `tests/fixtures/humor_replay.json` (30 сцен) проверяет `expected_action`, а не смешность. LLM-judge в replay не отделён от факта независимой оценкой.
- Legacy-карантин `legacy_humor_v1` корректен и в live retrieval не участвует — трогать не нужно.

Вывод: система не ремонтируется косметическими правками порогов. «Надо поднять participation_rate» или «опустить candidate_threshold» — бездоказательные решения; они увеличивают число плохих попыток, а не качество.

## 2. Целевая архитектура — один владелец качества

```
ambient trigger
  → единый gate (cooldown + минимальный разрыв + бюджет; один вход)
  → Writer: 2–3 кандидата, компактный JSON, частое should_attempt=false
  → детерминированные фильтры (шаблоны, отсутствующие имена, повторы, длина)
  → Critic (единственный judge; silence — валидный выбор)
  → send / silence / ❤️-react
  → feedback (heart, laugh, /funny, /unfunny) → активный вход в следующие Writer/Critic
```

Требования к архитектуре:

- один ясный путь решения «молчать / ответить / среагировать»;
- небольшой контекст сцены (`snapshot_scene_context`, ≤8 сообщений) и только релевантная память;
- минимальное число LLM-вызовов (Writer + Critic, без второго параллельного live-пайплайна);
- дешёвые детерминированные защиты от повторов, absent-person, объяснения шутки и токсичного шаблона;
- подтверждённые сигналы качества реально влияют на следующие ответы;
- измерение качества способно опровергнуть решение.

## 3. Шаги реализации

1. **Baseline-замер до правок.** Снять текущие значения `humor_metrics()` и распределение `reason_codes` из `humor_decisions_v2` в реальном `memory.json` (только агрегаты, без текстов). Зафиксировать, где именно сгорают попытки.
2. **Объединить pre-gate** в `conversation_policy.py`: убрать дублирующие счётчики `min_human_messages_between_replies`/`min_human_messages_between_checks`, оставить один порог в `snipe_allowed` + cooldown.
3. **Упростить Writer** (`adaptive_humor.py`): 2–3 кандидата вместо ровно 4; убрать из JSON поля, которые Critic реально не использует; поднять `director_max_tokens` 180→350, чтобы исключить обрезание JSON.
4. **Починить таймауты:** `interjection_timeout_seconds` 3→15 (или снять обёртку `_run_with_typing` для snipe).
5. **Активировать обратную связь:** негативные сигналы (`/unfunny`, текстовая критика) блокируют механизм + callback в следующих Writer-вызовах; позитивные — подсвечиваются как «работает у этого чата» (setup/механизм, без копирования текста).
6. **Создать quality-корпус** `tests/fixtures/humor_quality_scenes.json` (12–16 анонимизированных сцен): контекстный поворот, серьёзная тема, технический вопрос, законченная шутка человека, отсутствие повода, повтор недавней реплики, absent-person, шаблонный трек.
7. **Mocked-LLM e2e harness:** подмена `call_openai_metered` скриптованным JSON Writer/Critic, полный проход `text_handler → should_reply_decision → _maybe_send_adaptive_snipe → send_reply_with_style` с assert выбора gate.
8. **Replay-расширение** `humor_replay.py` на quality-корпус: old vs new prompt на одних сценах, LLM-judge считает anchor/freshness/tone, записывает вход/вердикт/стоимость; `--dry-run` перед реальным запуском.
9. **Финальный отчёт** по чек-листу промпта.

Текущие значения `candidate_threshold`/`participation_rate` не менять без результата шага 8.

## 4. Полное автоматическое тестирование

### Layer A — герметичные unit/integration (без сети и API)

1. Фикстура `tests/fixtures/humor_quality_scenes.json` (шаг 6). Для каждой сцены: `expected_gate` (JOKE/SILENCE/REACT), запрещённые имена/слова, `max_chars`, обязательный anchor-токен для JOKE-сцен, ожидания тишины по категории.
2. Для JOKE-сцен не фиксируется единственная «правильная» формулировка — проверяются свойства.
3. Unit-тесты `filter_candidates`: каждый плохой кандидат отклоняется по конкретной причине; каждый хороший проходит.
4. Тесты `parse_director`/`parse_critic_decision` на обрезанных/битых JSON.
5. Тест feedback→Writer: после `apply_feedback(rating="unfunny")` механизм блокируется; после positive — подсвечивается.
6. Тесты единого gate: cooldown, разрыв, бюджет без дублей счётчиков.
7. Existing-покров: `pytest -q tests/test_adaptive_humor.py tests/test_humor.py tests/test_conversation_policy.py tests/test_humor_replay.py`, затем `pytest -q` и `pytest -q tests/test_baseline_snapshots.py tests/test_refactor_parity.py`.

### Layer B — live LLM benchmark (ограниченная стоимость)

1. Расширенный `timur_bot.tools.humor_replay` на quality-корпусе: old-prompt vs new-prompt, слепое сравнение.
2. LLM-judge отделён от факта: в отчёте вход, кандидат, вердикт, стоимость; benchmark не называется доказательством смешности.
3. Запуск только с зафиксированным бюджетом вызовов и после `--dry-run`.

### Layer C — live-метрики

Агрегатные счётчики `gate_accuracy`, `anchoring_rate`, `template_violations`, `silence_precision` в `humor_metrics()` — для реального трафика без персональных данных в diff/тесты.

Ограничение: фикстуры не содержат сырой `memory.json`, Telegram-выгрузки и персональные данные целиком.

## 5. Что изменится и что сохранится

| Зона | Действие | Почему |
| --- | --- | --- |
| Cascade pre-gates | упростить до одного gate | каскад убивает попытки независимо от качества |
| Writer JSON | 2–3 кандидата, компактнее, `director_max_tokens` ↑ | убрать обрезание вывода и мусорные поля |
| `interjection_timeout_seconds` | 3 → 15 | два LLM-вызова не укладываются в 3 с |
| Feedback → генерация | реальная блокировка/подсветка механизмов | сейчас обратная связь только пишется |
| Critic | оставить, порог трогать до замера | независимый судья — рабочая защита |
| Детерминированные фильтры | оставить | дешёвая защита от повторов/имён/шаблонов |
| `legacy_humor_v1` | не трогать | карантин корректен |
| Direct-reply путь, Telegram-роутинг, подписки, privacy, vision, voice, Mini App, секреты | не менять | вне цели рефакторинга |

Данные пользователя не удаляются; изменение схемы состояния — с обратимой миграцией или безопасным чтением старого состояния.

## 6. Остаточный риск

LLM-judge и unit-тесты доказывают структурные свойства: тишину, шаблоны, повторы, зацепление, длину, gate-выбор. Смешность доказывается только человеком. Следующий эксперимент: анонимизированный корпус из реального чата + слепая ручная оценка 20–30 кандидатов old vs new владельцем без знания варианта.

## 7. Обязательный итоговый отчёт (по промпту)

1. Краткий диагноз с фактами из кода.
2. Что удалено, упрощено, оставлено и почему.
3. Как подтверждённый юмор теперь влияет на будущие ответы.
4. Какие тесты, replay и сравнения запущены и их результаты.
5. Что всё ещё нельзя доказать без реальных анонимизированных сцен и человеческой оценки.
